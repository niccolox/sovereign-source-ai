Data, Ontology, and Events

The sovereign ontology gives institutional knowledge a durable structure across applications, models, and workflows. It represents objects, relationships, and authorized actions while the data architecture separates current operational state from historical evidence. Governed events connect these views across time and organizational boundaries. Privacy policy determines which collection, derivation, movement, and use are permitted throughout that lifecycle.

Ontology as institutional source of truth

The ontology describes the institution in terms it owns. Its objects include actors, authority, intents, requirements, resources, capabilities, decisions, work orders, evidence, and outcomes. Relationships explain how those objects connect, while authorized actions define what may be done with them.

This structure bridges human understanding and executable systems. An interface can display a work order, an agent can reason about it, and a workflow can act on it without making any one application the sole owner of its meaning.

The ontology must survive implementation changes. Its definitions and institutional relationships remain portable when an application, model, storage system, or enterprise integration changes.

Operational state and historical evidence

The architecture assigns different responsibilities to different data components:

ComponentArchitectural role
Operational storeCurrent entities, permissions, relationships, and active state
Open table formatHistorical analytical datasets, snapshots, and reproducible views
Object storageRaw documents, datasets, artifacts, and evidence
Product analyticsExperience events, experiments, and outcome measurements
Lineage relationshipsConnections among sources, derivations, decisions, and actions

A transactional database such as Postgres, an open table format such as Iceberg, and product analytics such as PostHog are replaceable reference choices for these roles.

Historical data supports reconstruction of a decision against the data and feature state available at the time. Current operational state supports what the institution is permitted and prepared to do now. Neither should silently substitute for the other.

Observations, features, inferences, and declarations

Four classes remain distinct: raw observations, computed features, inferred attributes, and user-declared facts.

An observation records something captured from a source. A feature records a derivation. An inference expresses an interpretation with uncertainty. A declaration records what a subject explicitly stated. Converting these into a single undifferentiated profile would erase distinctions needed for explanation and governance.

Lineage connects source, observation, feature, inference, decision, and action. Inferences remain explainable and revocable, with their supporting observations preserved as distinct records.

Sovereign event architecture

Regional cells retain local operational authority and exchange governed events across boundaries. The architectural rule is local synchronous coordination and global asynchronous exchange.

An event gateway enforces identity, message integrity, schemas, classification, access policy, provenance, and audit. Idempotency and controlled replay make repeated delivery an explicit operational concern. Crossing a regional boundary does not itself transfer authority over the receiving institution’s actions.

Privacy as runtime policy

Data availability does not establish permission to use it. Policy governs collection, purpose, retention, joins, inference, model access, jurisdictional movement, capability access, deletion propagation, and human review.

A datum envelope can carry its source, subject, timestamp, confidence, authorization, purpose, sensitivity, permitted uses, and derivation lineage. This context allows privacy constraints to accompany data into later decisions.

Reference implementation

A reference build combines an institutional ontology, transactional state, historical tables, raw-evidence storage, an event gateway, analytics, and externally enforced policy. Derived features and inferences retain links to their sources. Permitted capabilities consume governed views, and outcomes return through the evidence loop.
